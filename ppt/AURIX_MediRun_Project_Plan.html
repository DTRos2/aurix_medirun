1. 프로젝트 개요

AURIX MediRun은 공공장소에서 응급 상황이 발생했을 때, 현장 SOS 버튼 하나로 119 모의 신고, 관리자 알림, 응급 키트 로봇 출동, 음성 안내를 동시에 시작하는 응급 대응 보조 시스템입니다.

팀명

AURIX · Autonomous Robotics for Intelligent eXperience

팀원

도희정 · 최치언

핵심 가치

관리자를 기다리지 않는 현장 즉시 호출 구조

프로젝트 범위

의료 판단이 아닌 모의 응급 키트 운반·안내·기록

2. 문제 정의

공공장소는 넓고 복잡하여 응급 상황 발생 위치를 빠르게 설명하기 어렵습니다. 또한 관리자가 직접 호출해야 하는 구조는 초기 대응을 지연시킬 수 있습니다. MediRun은 현장에서 바로 누를 수 있는 SOS Station을 통해 신고 정보와 로봇 출동 정보를 동시에 전달하는 구조를 제안합니다.

위치 설명 지연

지하철·도서관·청사처럼 넓은 실내에서는 정확한 위치 설명이 어렵습니다.

관리자 의존 한계

관리자가 직접 화면을 열어 호출하면 초기 대응이 늦어질 수 있습니다.

응급 키트 접근성

키트·AED 위치를 모르면 주변 사람이 찾는 데 시간이 걸립니다.

혼잡한 통로

사람이 많은 곳에서는 로봇이 이동 중임을 알려 통로를 확보해야 합니다.

3. 목표와 MVP 범위

항목내용
구현 목표SOS 버튼을 누르면 emergency_event가 생성되고 관리자 대시보드와 로봇 출동이 동시에 시작된다.
로봇 목표TurtleBot3가 지정 waypoint까지 응급 키트 박스를 싣고 이동한다.
안전 목표LiDAR 기반 전방 장애물 정지와 저속 주행을 적용한다.
기록 목표호출 시각, 출동 시각, 도착 시각, 장애물 이벤트를 로그로 남긴다.
제외 범위실제 119 자동 신고, 환자 진단, 의료 판단, 치료 지시, 혼잡 플랫폼 주행
실제 119 연동은 기관 협의와 승인, 통화 품질 검증, 위치 등록, 개인정보·녹취 기준이 필요한 영역입니다. 본 프로젝트는 모의 신고 서버로 시연합니다.

4. 서비스 시나리오

1. 발생

공공장소에서 부상자 또는 응급 상황이 발생합니다.

2. 호출

주변 사람이 벽면 SOS 버튼을 1.5초 이상 누릅니다.

3. 동시 실행

모의 119 신고, 관리자 알림, 로봇 출동, 현장 안내가 동시에 시작됩니다.

4. 도착·기록

로봇이 키트를 전달하고, 출동 시간·도착 시간·장애물 이벤트를 저장합니다.

데모 장면

도서관 열람실 또는 지하철역 대합실을 가정합니다. 주변 사람이 SOS 버튼을 누르면 관리자 화면에 위치가 표시되고, TurtleBot3가 응급 키트 박스를 싣고 해당 구역으로 이동합니다. 이동 중에는 스피커로 통로 양보 안내를 재생합니다.

5. SOS Station 설계

SOS Station은 공공장소 벽면에 설치되는 현장 호출 장치입니다. 버튼은 단순 입력이 아니라 위치 정보와 통화·안내 기능까지 포함하는 응급 호출 포인트입니다.

구성설명
SOS 버튼보호 커버 + 길게 누르기로 오작동 감소
마이크/스피커통화 연결음·현장 안내·상황 전달
고정 위치 IDGPS 대신 “역사 B1 A구역” 같은 등록 위치 사용
QR/NFC 보조 호출방문객이 휴대폰으로 위치 기반 호출 페이지 접근
상태 표시등신고 접수, 로봇 출동, 도착 상태 표시
실내에서는 GPS보다 버튼마다 미리 등록된 고정 위치 ID를 사용하는 편이 정확하고 현실적입니다.

6. 시스템 아키텍처

Emergency Dispatcher가 중앙 허브가 되어 버튼 이벤트를 119 모의 신고, 관리자 알림, 로봇 출동, 음성 안내, 로그 저장으로 동시에 분기합니다.

구성 요소역할
SOS Station응급 상황을 현장에서 입력하고 위치 ID를 전달
Emergency Dispatcher이벤트를 받아 여러 기능을 동시에 실행
Location Mapperbutton_id를 정확한 장소명과 waypoint로 변환
Mission Manager/Nav2로봇의 목적지 이동을 실행
Event Logger호출·출동·도착·정지 이벤트 기록

7. 초보자용 설명

처음 보는 사람은 MediRun을 “응급상황 버튼 + 로봇 내비게이션 + 출동 기록장”이 합쳐진 서비스로 이해하면 됩니다.

용어쉽게 설명하면
SOS Station응급 상황을 알리는 벽면 호출 장치
Emergency Dispatcher버튼 신호를 받아 119·관리자·로봇으로 나눠 보내는 교통정리 담당
Nav2로봇용 내비게이션. 목적지까지 가는 길을 계산
LiDAR로봇의 눈. 앞에 사람이 있으면 거리로 감지
Logger언제 호출했고 언제 도착했는지 기록하는 출동 일지

10. 음성 안내와 현장 UX

상황안내 문구/정책
이동 중“응급 키트 배송 중입니다. 통로를 비워주세요.”
장애물 정지“앞쪽 통로가 막혀 정지합니다. 잠시 비켜주세요.”
도착“응급 키트가 도착했습니다. 119 안내에 따라 사용해 주세요.”
주의 문구공포감을 주는 반복 경보보다 침착한 안내 문구 사용

음성 안내는 불필요한 공포를 주기보다 주변 사람이 통로를 비우고 119 안내를 따르도록 차분하게 유도하는 방향으로 설계합니다.

11. 안전·책임 범위

구분내용
실제 서비스소방·시설 운영기관 협의, 통화 품질, 위치 등록, 개인정보·녹취 기준 필요
프로젝트 MVP실제 119 전화 대신 “모의 신고 화면”과 관리자 알림으로 시연
로봇 역할응급 키트 운반, AED 위치 안내, 통로 양보 안내, 로그 기록
제외 역할환자 진단, 의료 판단, 119 신고 대체, 치료 지시
MediRun은 119와 사람의 응급 대응을 대체하지 않습니다. 응급 키트 운반, 위치 안내, 통로 양보 안내, 출동 로그 기록을 담당하는 보조 시스템입니다.

13. 구현 일정

기간작업 내용
1-2일차TurtleBot3 bringup, /scan·/odom 확인, 기본 주행 테스트
3-4일차SLAM 맵 작성, SOS 위치별 waypoint 설정
5-6일차웹 SOS 버튼, emergency_dispatcher, 관리자 알림 구현
7-8일차Nav2 출동, 음성 안내, LiDAR 안전 정지 연결
9-10일차반복 테스트, 로그 리포트, 발표 영상·슬라이드 정리

14. 평가 기준

평가 항목목표/측정 방법
호출 반응 시간SOS 버튼 후 dispatcher 이벤트 생성까지 1초 이내
출동 성공률5~10회 반복 중 waypoint 도착 성공률 80% 이상
평균 도착 시간데모 코스 기준 2분 이내
안내 음성 작동이동·정지·도착 상태별 음성 재생 성공
로그 완성도시간, 위치, 결과, 장애물 이벤트 필수 필드 100% 기록

15. 비용·사업화 전략

항목전략
웹 SOS 버튼개발 비용 중심, 추가 하드웨어 거의 없음
QR/NFC 보조 호출출력물·태그 기반으로 저비용 확장 가능
물리 버튼 1개ESP32/버튼/케이스/전원으로 발표용 대표 장치 제작
상용 119 연동기관 협의와 승인 필요. 본 프로젝트 범위에서는 제외

사업적 방향

설치형 PoC

공공장소 한 구역에 SOS Station과 로봇 출동 경로를 구축

운영 SW

관리자 알림, 위치 매핑, 로그 리포트 제공

유지보수

맵 재작성, 경로 점검, 배터리·부품 관리

확장

여러 구역의 버튼과 다중 로봇 출동 관리

16. 리스크와 대응

리스크대응 방안
오작동 호출보호 커버, 길게 누르기, 관리자 확인 로그
혼잡한 통로저속 주행, 음성 안내, 안전 정지, 제한 구역 운행
네트워크 장애로컬 네트워크 우선, 실패 시 수동 호출 절차 안내
개인정보·녹취MVP에서는 실제 개인정보 저장 없이 이벤트 시간·위치만 기록
의료 책임진단·치료 지시는 하지 않고, 119 안내와 사람의 대응을 보조
