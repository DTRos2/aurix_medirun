AURIX MediRun 발표 대본

Team AURIX · 도희정 · 최치언 · 20장 슬라이드 기준

슬라이드 01. AURIX MediRun

안녕하세요. 저희는 AURIX 팀의 도희정, 최치언입니다. 저희가 제안하는 주제는 AURIX MediRun입니다. 공공장소에서 응급 상황이 발생했을 때, 현장 버튼 하나로 응급 키트 로봇을 호출하고 관리자에게 알리며, 모의 119 신고까지 동시에 실행하는 응급 대응 보조 시스템입니다.

슬라이드 02. 팀명: AURIX

팀명 AURIX는 Autonomous Robotics for Intelligent eXperience의 의미를 담고 있습니다. 쉽게 말하면 자율 로봇 기술로 더 나은 미래 공간과 새로운 경험을 만들겠다는 뜻입니다.

슬라이드 03. 왜 필요한가?

이 프로젝트가 필요한 이유는 응급 상황에서 시간이 매우 중요하기 때문입니다. 넓은 공공장소에서는 정확한 위치 설명이 어렵고, 관리자가 직접 호출해야 하면 초기 대응이 늦어질 수 있습니다.

슬라이드 04. 핵심 아이디어

저희의 핵심 아이디어는 현장 버튼 하나로 여러 기능을 동시에 시작하는 것입니다. 버튼을 누르면 모의 119 신고, 관리자 알림, 로봇 출동, 음성 안내가 한 번에 실행됩니다.

슬라이드 05. 서비스 시나리오

시나리오는 간단합니다. 공공장소에서 응급 상황이 발생하면 주변 사람이 SOS 버튼을 누릅니다. 시스템은 위치를 확인하고, 로봇은 응급 키트를 싣고 해당 구역으로 이동합니다.

슬라이드 06. MediRun SOS Station

SOS Station은 단순 버튼이 아닙니다. 버튼, 스피커, 마이크, 위치 ID, QR 또는 NFC 호출 기능을 포함한 현장 장치입니다. 실내에서는 GPS보다 미리 등록된 위치 ID가 더 정확합니다.

슬라이드 07. 전체 아키텍처

전체 구조는 Emergency Dispatcher가 중심입니다. SOS Station에서 이벤트가 들어오면 Dispatcher가 119 모의 신고, 관리자 알림, 로봇 출동, 로그 저장을 나누어 실행합니다.

슬라이드 08. 초보자용 설명

어려운 용어를 쉽게 설명하면, SOS Station은 호출 버튼, Dispatcher는 교통정리 담당, Nav2는 로봇 내비게이션, LiDAR는 로봇의 눈, Logger는 출동 일지입니다.

슬라이드 09. 로봇 출동 흐름

로봇은 의료 판단을 하지 않습니다. 호출 위치로 이동하고, 사람에게 통로를 비워 달라고 안내하고, 도착 시간과 장애물 이벤트를 기록하는 역할을 합니다.

슬라이드 10. 위치 전달 방식

위치 전달은 GPS가 아니라 고정 위치 ID 방식으로 설계했습니다. 예를 들어 STN-B1-A-03이라는 버튼 ID가 지하 1층 A구역, 특정 waypoint, 특정 CCTV 위치와 연결됩니다.

슬라이드 11. 119 연동 범위

실제 119 연동은 기관 협의와 승인이 필요한 영역입니다. 그래서 1차 프로젝트에서는 실제 신고가 아니라 모의 신고 화면으로 구현하고, 관리자 알림과 로봇 출동 흐름을 검증합니다.

슬라이드 12. 하드웨어 구성

하드웨어는 TurtleBot3 Burger, 응급 키트 박스, SOS 버튼 장치, 스피커와 LED, Remote PC로 구성합니다. 물리 버튼이 어렵다면 웹 SOS 버튼으로도 데모가 가능합니다.

슬라이드 13. 소프트웨어·ROS 2 설계

소프트웨어는 역할별 노드로 나눕니다. 버튼 입력 노드, emergency dispatcher, mission manager, safety monitor, sound alert node, event logger가 서로 메시지를 주고받습니다.

슬라이드 14. 음성 안내 UX

사람이 많은 장소에서는 음성 안내가 중요합니다. 로봇은 “응급 키트 배송 중입니다. 통로를 비워주세요.”처럼 차분하지만 명확한 안내를 재생합니다.

슬라이드 15. 주행 공간 설계

주행 공간은 처음부터 지하철 전체가 아니라 안전한 제한 구역으로 설정합니다. 계단, 에스컬레이터, 플랫폼 가장자리는 제외하고, 대합실이나 안내데스크 주변처럼 안전한 구역에서 검증합니다.

슬라이드 16. 2주 구현 일정

구현 일정은 2주 기준입니다. 먼저 TurtleBot3와 센서를 확인하고, SLAM 맵과 waypoint를 만든 뒤, SOS 버튼과 dispatcher, 로봇 출동, 음성 안내, 로그 저장을 차례로 연결합니다.

슬라이드 17. 평가 지표

평가 기준은 호출 반응 시간, 출동 성공률, 평균 도착 시간, 음성 안내 작동 여부, 로그 완성도입니다. 단순히 움직였다는 것보다 반복 테스트 결과를 보여주는 것이 중요합니다.

슬라이드 18. 비용·MVP 전략

비용 측면에서는 웹 SOS 버튼과 QR 호출은 거의 추가 비용이 없고, 물리 버튼은 대표 장치 하나만 만들어도 충분합니다. 상용 119 연동 시스템은 프로젝트 범위에서는 제외합니다.

슬라이드 19. 리스크와 대응

응급 관련 주제이기 때문에 안전과 책임 범위를 명확히 해야 합니다. MediRun은 환자를 진단하거나 치료를 지시하지 않고, 119와 사람의 대응을 보조하는 역할만 합니다.

슬라이드 20. 사업적 확장성

마지막으로 MediRun은 로봇 판매보다 공공장소 응급 대응 보조 서비스로 확장할 수 있습니다. 저희는 현장 버튼 하나로 응급 대응 흐름을 시작하는 자율 로봇 서비스를 제안합니다. 감사합니다.
